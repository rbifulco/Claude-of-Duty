## Coordinates, material preflight and limitations

World uses metres and Y up. Level→world is rotation Y=0.5877 followed by translation (0.9,0,1.34); inverse is world.worldToLevel, or the complete inverse A.xform for orientation/scale. Building owner pivots use A.toWorld(spec.x,0,spec.z). Child feedback is parent-local; apply ownership transforms once. Canonical prop feedback remains local to the original prototype; static components retain building-local origins, not independently centered fragment pivots.

Custom shader injection uses generated GPU albedo/ORM/normal maps, dominant-axis/triplanar projection, parallax, macro variation, procedural weathering and RGB vertex masks. Review uses exact geometry and a supported PBR approximation: read back generated texture pixels, preserve supported map channels, generate dominant-axis UVs when the original material is not mesh-UV, and disable RGB masks as vertex colors. SDK 0.7.0 omits alphaTest and normalScale: alpha-tested source maps therefore export a separate source-derived binary alphaMap and an opaque albedo map, preserving cutouts; normalScale and shader normal-amplitude differences remain explicitly unsupported. Triplanar blending, parallax, weathering, lighting, shadowing and postprocessing are not reproduced by the editor. These are explicitly unsuitable for final appearance signoff; the live game remains authoritative. Geometry, openings, authored components, placement, scale and construction evidence remain available. Generated maps have no remote URL or embedded credentials and are delivered by the live resource bridge.

This new baseline deliberately reduces subject scope compared with the previous production integration: its six boot-state AI combatants are not registered. The planned review is environment construction and composition; moving a frozen AI boot pose does not map to a durable authored environment placement. Weapons, HUD, transient effects, invisible collision and light helper objects remain excluded. Authored environment geometry includes micro-detail and props rather than replacing it with coarse proxies.

### Verified before publication

- Exact original comparison in `world-check.json`: identical SHA-256 digest of all render/collision geometry buffers, instance matrices/masks, plus identical light placements, stats and RNG with capture observer disabled and enabled.
- Ordinary hero view at frame 15: **pixel-identical**, zero changed RGBA channels (`pixel-parity.json`). Movement remained 2.07052065m, firing remained 7 events, and renderer counts were identical. Representative input took 544ms before and 532ms after. Startup 11.18s before versus 3.92s after is not a cold-start speedup claim: shader caches warmed across the session; it is evidence of no observed regression, supplemented by source isolation and exact renderer parity.
- Capture bootstrap: 5.02s initial sample, 1.77s warm editor sample. Complete metadata was published before any deferred asset production. Initial separate-placement catalog took 54.3ms; actual editor rejected 8,034 actors under its 5,000-actor limit. The final micro-context representation resolves that identified limit without altering editor protections or removing geometry.
- Generated textures were successfully read through SDK live-resource APIs as decodable PNG bytes. Initial BE1 detail was 1,929,759 geometry bytes; satellite dish detail was 31,227 bytes. These source-side checks are separate from editor texture hydration acceptance.
- Initial attempt to verify local capture in the hosted editor was blocked by automatic approval review. No workaround was used. Local editor acceptance continues; intended public-site verification will use the user's recorded explicit official-editor public URL authorization after separate publication.

Canonical prop factories originally merge their subparts into one BufferGeometry. This integration preserves that exact canonical mesh, source normals/UV evidence and supported material maps, but does not invent separately editable dish-bowl/mount or AC-grille parts. Building component boundaries are captured at the authoritative generator phases; finer prop-component source edits require the canonical factory and surface feedback. The micro-detail context families preserve source ordering and every instance matrix; they are aggregate editing subjects, not independent Scene placements.

The baseline is exactly local `main` and `upstream/main` at d9b237b; Git confirms it is an ancestor of the fresh branch. The existing repository remote default (`spatial-review`) was deliberately not used as the original baseline.

Build identity includes both Git commit and a deterministic SHA-256 fingerprint of source files and the lockfile. Vite invalidates the virtual build module for source changes, so local feedback/source refresh checks also receive a changed build identity. Production workflows supply the exact publication commit; geometry, maps and metadata revisions share that immutable build identity.

Bootstrap intentionally constructs the original world once to establish exact geometry-derived bounds and placement metadata. It does not boot AI, audio, gameplay simulation, or postprocessing. The current SDK has no producer-controlled initial progress gate; the bridge attaches only after every initial registration is complete. Deferred producers retain exact source buffers, create/serialize requested families on demand, yield between construction groups, honor SDK byte checks and cancellation, and dispose partially generated owned geometry on cancellation. Capture caches are bounded by the finite source-build asset/family set; SDK snapshot/resource caches add their installed bounds and 60-second deferred texture delivery grace. Pagehide/HMR detaches and disposes capture-owned resources.

Building layout records author X/Z footprints rather than arbitrary per-building Euler rotations. Position feedback maps through the inverse level transform to those records. A requested building rotation or nonuniform scale requires changing the generator and matching collision/light responsibilities; applying that feedback only to the capture graph would be incorrect. Static component nodes retain the source assembly frame rather than recentered mesh pivots.
