01
What is Spatial Review?

Spatial Review is a shared layer between a live web experience and the people—or agents—working on it. It turns a visual, interactive scene into inspectable project context.

Instead of flattening a spatial experience into a screenshot, it keeps the camera, scene structure, routes, assets, and feedback connected. Everyone can discuss the same place with the same references.

02
Why it exists

A screenshot shows an outcome. Spatial Review preserves the intent behind it.

01
See beyond pixels

Review the scene graph, camera paths, assets, and live experience together—not as disconnected evidence.

02
Point to the right thing

Feedback stays anchored to exact objects, moments, and sources, reducing ambiguity across every iteration.

03
Give agents usable context

Structured review data can travel back into a coding workflow, so an agent can understand and act on intent.

03
How it connects to the editor

The website remains the source experience. The editor becomes the place where its spatial context is inspected and discussed.

01
WEBSITE
Publish a discovery document

An integrated site exposes a small manifest at /.well-known/spatial-review.json, pointing to its scene, assets, and review capabilities.

02
CONNECTION
Load the project context

Paste the site URL here. Spatial Review discovers the available documents or asks the live site for a capture, then prepares a local review workspace.

03
EDITOR
Review in the right view

Move between scene, experience, and asset views. Follow paths, inspect exact sources, and leave feedback where it belongs.

04
AGENT HANDOFF
Return structured feedback

The resulting context is explicit enough for a coding agent to trace the request back to the relevant place and make a targeted change.
